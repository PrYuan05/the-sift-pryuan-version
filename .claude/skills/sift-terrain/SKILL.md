# Sift terrain and biome design

How The Sift's terrain is built and how to change it safely. Everything is data generated by Python
(`tools/worldgen/build_the_sift.py`); the game only reads the JSON. Reply to the user in Traditional Chinese.

## 1. Understand the request first
- Reference images: describe what you see (wall height vs floor, number of terraces, what is on tops / walls / floors,
  where water is). Wiki pages (minecraft.wiki `Dungeons_II:*`) are thin; read them with the built-in browser
  (`api.php?action=query&prop=extracts&explaintext=1&titles=...` returns plain text) and use them for theme, mobs, names.
- Identify blocks by their zh_tw names: `grep '"block.pysift.<id>": "<名稱>"' src/main/resources/assets/pysift/lang/zh_tw.json`.
  Check a block's states before using them (`blockstates/<id>.json` keys, e.g. `bleach=0..4`, `veining=0..3`).
- Ask (AskUserQuestion) only what changes the build: where the biome goes / what it replaces, wall height, material
  order (e.g. light at the wall foot -> gold at the water), which texture stages to touch. Then write a plan.

## 2. Where things live in build_the_sift.py
| piece | what to edit |
| :--- | :--- |
| biome list / climate | the `point(...)` entries of the multi-noise biome source at the end; a point is (temperature, humidity, weirdness) ranges |
| landform of each biome | splines over noises (`HILLS`, `RIDGE`, `LAND`...) combined in the terrain `SHAPE` -> `overworld/offset` |
| surface materials | the material rule (`wj(D / "worldgen/material_rule/the_sift.json", seq(...))`), one `in_biome(...)` per biome |
| biome JSON (sky, spawns, features) | `biome(name, temperature, downfall, rain, sky, fog, water, spawns(...))` |
| plants | `VEGETATION[biome]` (`patch`, `carpet_patch`, `wall_plant`, `cliff_vines`) |
| plants must be allowed on the floor | add the floor block to `#minecraft:supports_vegetation` (`tools/worldgen/build_vegetation.py` list + the tag JSON) |
| other per-biome lists | `ModSounds.SIFT_BIOMES` + `build_sift_audio.py`, `SiftPortalBlock.PORTAL_DESIGNS`, `BlubEntity` variant, `build_landmarks.py` `SIFT_BIOMES`, `LANDMARK_FEATURES` |

## 3. Placing a new biome without shrinking the others
Carve it out with a dimension the old biomes do not use, e.g. weirdness:
- new biome: `point("new", [0.0, 1.0], FULL, [0.42, 1.0])`; give the biomes it may replace `NOT_NEW = [-1.0, 0.42]`
  (leave biomes it must never replace at FULL). Overlapping boxes tie, so split the weirdness range exactly.
- the terrain must switch at the same place: build the new landform as its own density function and blend
  `shape = climate + weight * (new - climate)` where `weight` is a raw spline over `pysift:the_sift/ridges`
  (0 below ~0.38, 1 above ~0.46) times a temperature spline if the biome is limited to warm areas.
  Put each spline in its OWN density-function file (`terrain/climate_shape`, `terrain/<new>_shape`, `terrain/<new>_weight`)
  - nesting the old shape inside a new spline copies it several times (offset.json grew to 13 000 lines once).
- `spline(coordinate, (location, block_height_or_nested_spline, slope))` converts heights with `to_offset`;
  for weights use a raw spline (values are not heights).

## 4. Landforms that look built, not noisy
- Canyon network: `abs(noise)` (cache it as `terrain/<name>_canyon`) is 0 along long winding lines. A spline over it with
  FLAT shelves (slope 0 over a range) joined by tiny location steps (0.006) gives vertical walls and terraces:
  river bed (below sea level 63 -> fills with spirit liquid) | bank | half step | land layer | wall | terraces | plateau.
- The horizontal size of everything depends on how fast the noise changes per block. MEASURE it on the test server
  (section render) and size the shelves from that (Lullaby Hills: base_octave -7 -> ~0.011 per block, shelves 0.065 = ~6 blocks).
  base_octave -8 turned the whole canyon into a 100-block gentle slope; first guesses are usually off by 2x.
- Keep caves below the surface (`bury_caves`) and the steep `FACTOR` - they are already wired in.

## 5. Surface materials and natural transitions (user rule)
Every border between two materials must interpenetrate block by block: A -> 25 % B -> 75 % B -> B, with the shares
drifting about +-10-25 % from place to place. The helpers in build_the_sift.py do this - reuse them:
- `mix(share, a, b)`: b on ~share of the blocks (fine dither noise `pysift:the_sift_dither`, base_octave 0), share
  drifting +-`DITHER_JITTER` with the low `minecraft:surface` noise. `DITHER_SD` turns shares into thresholds; it was
  measured (0.38) - re-measure if you change the dither noise (count blocks in a pure mixed band on the test server).
- `canyon_band(lo, hi, rule)`: rule where lo <= |canyon noise| < hi. Surface rules CANNOT read density functions; they
  can read the same NOISE with `noise_threshold` at the same coordinates (both sample (x, 0, z) at scale 1), so bands
  line up with the terrain layers built from that noise.
- `blended_bands(materials, borders, width)`: a whole sequence of bands with the 25 / 75 % blend at each border.
- Composite materials are just rules: `SANDSTONE = mix(0.15, bleach0, bleach1)`.
- Apply the same banding under the floor (`WITHIN(3)`) so step faces match, and give walls enough depth
  (`WITHIN(26)` when walls are ~22 tall) or the lower wall shows the deep base stone.
- Do not split materials by absolute Y when they meet on the same floor - that is what made hard, blocky borders.

## 6. Generate, then verify on the test server
1. Commit first if the user agrees (CLAUDE.md: commit before big resource changes; never add `*.zip` or
   `sift_visual_corrected/`). Check the game client is not running before any Gradle task:
   `Get-CimInstance Win32_Process | ? { $_.CommandLine -match 'dli\.env=client' -and $_.Name -match 'java' }`.
2. `python -I tools/worldgen/build_the_sift.py . build/worldgen_ref/data/minecraft/worldgen/noise_settings/overworld.json`
   then ALWAYS `python -I tools/worldgen/build_landmarks.py .` (build_the_sift wipes worldgen/feature and placed_feature,
   which deletes the landmark features). `git status` must show no unexpected deletions.
3. `.\gradlew.bat compileJava` if Java changed; `python -I tools/texture_pipeline/verify.py .` -> `errors: []`.
4. Test server: `./gradlew.bat runSiftTestServer` in the background; wait for `Done (` (and stop waiting on
   `BUILD SUCCESSFUL` / `Failed to start` - a datapack error makes it exit quietly; read the log for `Caused by`).
   Configured features live in `worldgen/feature/` in 26.3; advancement `player` conditions are one object
   (`{"type": "minecraft:entity_properties", "predicate": {"minecraft:location": ...}}`).
5. Old chunks never change: locate the biome from FRESH far coordinates
   (`devserver.py cmd "locate biome pysift:<id>"` positioned at e.g. 30000 0 -30000), then
   `devserver.py gen 128 90 <x> <z>` and render: `python -I .claude/skills/sift-terrain/scripts/render_area.py <x> <z>`.
   Look at the top view (material bands, blends, water) and both sections (wall heights, shelves, layers), compare with the
   reference, adjust numbers, regenerate, and look again. Also `locate biome` every other biome to make sure they still exist.
6. After stopping the server, wait until it has exited before regenerating (Windows keeps the files locked:
   "Invalid argument" on write).
7. Send the renders to the user (SendUserFile) and say plainly what was verified on the server and what still needs an
   in-game look. Update CHANGELOG.md and README (both languages). Do not commit unless asked.

## Gotchas
- Region scans (`blocks_in_box(..., with_props=True)`) omit properties for default states - match the bare id.
- Bash heredocs choke on some Python/Java snippets: write longer patch scripts with the Write tool into the scratchpad.
- Trees, leaves and logs are solid: anything that measures "the ground" must skip `#minecraft:leaves` / `#minecraft:logs`.
- `build_vegetation.py` lists must not contain deleted blocks (a stale id breaks the tag when it is regenerated).
